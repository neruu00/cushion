# Cushion

> 쿠션이 완충해 토큰을 줄인다.

**에이전트를 1차 독자로 삼은 문서 도서관이다.** 스펙과 ADR, 런북, 회의록, 용어집처럼
흩어지기 쉬운 프로젝트 문서를 한곳에 모아 두고, 팀에는 변경 알림을 보내고,
에이전트에는 MCP로 **필요한 조각만** 읽고 쓰게 한다.

목적은 하나다. 에이전트가 같은 문서를 세션마다 컨텍스트에 다시 싣느라 소모하는 토큰을
줄이는 것이다.

**이 레포 자신의 문서로 측정한 값**은 문서를 전부 불러올 때와 비교해서
**20% 미만, 곧 5배 이상 절감**이다(작업 3건 기준, 목차 1회 + 필요한 섹션 1개씩).
목차는 세션당 한 번만 읽으면 되므로 작업이 늘어날수록 격차는 더 벌어진다.

숫자를 코드에 고정하지는 않는다. 측정 대상이 이 레포의 문서라서 문서가 자라면 값도 함께
움직이기 때문이다. `pnpm acceptance`가 실행될 때마다 다시 측정하고, 그 방법은 Cushion의
`PLAN.md` T-601에 있다.

---

## 어떻게 동작하나

```
                       Cushion
                    ─────────────
사람     ─웹 편집→   documents          (원본)  ─MCP→  에이전트
에이전트 ─doc_put→   document_versions  (이력)  ─→     웹 화면
                     sync_events        (요약)  ─→     Mattermost · Discord
```

**문서의 원본이 여기에 있다.** 예전에는 git 레포의 `.md`를 비추는 미러였다. 그런데 남의 레포
문서를 고치려면 클론이 필요했다. 읽으려고 클론을 피하게 해 주는 도구가 정작 쓰려면 클론을
요구하는 셈이어서 방향을 뒤집었다(PLAN `D-011`).

그래서 git이 공짜로 주던 것을 대신할 장치를 따로 두었다.

- **이력**: 덮어쓰기 전에 이전 본문을 남긴다. 문서를 지워도 이력은 남는다
- **동시 편집**: 읽을 때 받은 `sha`를 쓸 때 되돌려 받는다. 어긋나면 **거부**하고 병합하지 않는다
- **내보내기**: `/api/export`. git이 없으므로 이것이 유일한 백업이다

## 시작하기

> **쓰려고 왔다면** 이 레포를 받을 필요가 없다. 배포본의 `/docs`에 개요와 설치, 사용법, 스킬이
> 있고 로그인하지 않아도 읽을 수 있다. 아래는 **직접 띄우려는 사람**을 위한 안내다.

준비물은 Node 24 이상, pnpm, Supabase 프로젝트, Google OAuth 클라이언트다.

```bash
pnpm install
cp .env.example .env.local     # 값을 채운다
```

`SUPABASE_SERVICE_ROLE_KEY`에는 반드시 **`service_role` 키**를 넣는다. anon 키를 넣으면
RLS 정책이 0개라서 모든 읽기가 빈 결과로, 모든 쓰기가 거부로 끝나는데 **에러가 나지 않아
조용하다.** "화면이 비어 있다" 또는 "아무 일도 일어나지 않는다"면 이 키부터 확인한다.

`supabase/migrations/0001_schema.sql`을 Supabase SQL Editor에서 실행한다(멱등하다).
그다음에 개발 서버를 띄운다.

```bash
pnpm dev
```

`ADMIN_EMAILS`에 넣어 둔 이메일로 로그인하면 `/admin`이 열린다.

| 목적 | 명령 |
|---|---|
| 개발 서버 | `pnpm dev` |
| 전체 검증 | `pnpm verify` (타입 + 린트 + 테스트 + 빌드) |
| 인수 검증 | `pnpm acceptance` (SPEC §11을 실 DB로 검증하며, dev 서버가 떠 있어야 한다) |

## 라이브러리 만들기

**로그인하면 누구나 만들 수 있다**(`D-013`). `/dashboard`의 "새 라이브러리"로 만들고,
만든 사람이 첫 멤버이자 **소유자**가 된다. `/admin`은 전체를 조망하고 내보내는 화면이지
라이브러리를 만드는 곳이 아니다.

팀원은 라이브러리 화면의 **멤버** 다이얼로그에서 초대한다. 이메일을 하나씩 넣거나, 초대 링크
하나를 만들어 채널에 던져도 된다(`D-023`). 초대와 제거, 설정 변경은 소유자만 할 수 있고,
자기 자신을 빼고 나가는 것은 누구나 할 수 있다(`D-021`).

**멤버가 아닌 이메일은 로그인해도 아무것도 못 본다.** 예외는 소유자가 공개 읽기를 켠
라이브러리뿐이다. 그때는 링크를 아는 누구나 로그인 없이 문서를 읽을 수 있지만, 쓰기와 이력,
멤버 목록은 그대로 멤버에게만 열린다(`D-024`).

문서는 `/libraries/[library]` 화면의 "새 문서"로 만들거나 에이전트가 `doc_put`으로 만든다.
경로는 `.md`로 끝나야 한다. 목차와 섹션 조회가 전부 마크다운을 전제하기 때문이다.

**읽기와 쓰기의 기준이 같다.** 볼 수 있는 사람은 고칠 수 있고, 역할을 더 나누지 않는다.

## 에이전트 붙이기

`/settings/tokens`에서 발급하면 붙여넣을 명령이 토큰이 채워진 채로 함께 나온다.
아무 디렉터리에서 한 번 실행하면 끝나고, **레포를 받을 필요도 환경변수를 설정할 필요도 없다.**

```
claude mcp add --transport http --scope user cushion https://<cushion>/api/mcp --header "Authorization: Bearer cshn_pat_..."
```

여기에 토큰을 직접 넣는 이유는 이 명령이 쓰는 `~/.claude.json`이 커밋되지 않기 때문이다.
평문으로 남으므로 유출되면 재발급한다. 재발급하는 순간 이전 토큰은 무효가 된다.

Claude Code 외에 Antigravity와 Codex CLI용 설정도 같은 화면이 클라이언트별로 만들어 준다.
레포에 커밋해서 팀 전체에 배포하고 싶으면 `.mcp.json`을 쓴다. 그 파일은 커밋되므로 토큰을
넣지 않고 환경변수(`CUSHION_TOKEN`) 확장을 쓴다. 라이브러리를 만들 때 나오는 결과 화면이
그 스니펫과 `AGENTS.md`에 덧붙일 문구를 함께 낸다.

| 툴 | 하는 일 |
|---|---|
| `doc_outline` | 문서 목록과 `##` 헤딩만 준다. **이것을 먼저 부른다** |
| `doc_get` | 문서 하나 또는 섹션 하나. `if_none_match`가 맞으면 본문 대신 `unchanged`를 준다 |
| `doc_search` | 매칭된 섹션 상위 몇 개를 준다 |
| `doc_changes_since` | 커서 이후의 변경 요약을 준다. 커서는 서버가 기억한다 |
| `doc_put` | 생성하거나 수정한다. 기존 문서는 `base_sha`가 필수이고, 어긋나면 거부하며 현재 sha를 준다 |
| `doc_delete` | 삭제한다. 이전 본문은 이력에 남는다 |
| `library_create` | 새 라이브러리를 만든다. 부른 토큰의 주인이 첫 멤버가 된다 |

구독에는 폴링도 상시 연결도 쓰지 않는다. 밀렸을 때만 아무 툴 응답 끝에 한 줄이 붙는다.

```
[stale] <library>: <path> changed — call doc_changes_since
```

밀리지 않았으면 그 줄이 아예 없으므로 **추가 비용이 0이다.**

**툴이 있다고 해서 에이전트가 알아서 쓰지는 않는다.** 프로젝트의 `AGENTS.md`에 몇 줄을 넣어야
비로소 쓴다. 그 문구도 위의 라이브러리 생성 결과 화면이 출력해 주고, `/cushion-use` 스킬이
`git remote`를 보고 대신 넣어 주기도 한다.

## 스택

Next.js **16** App Router · Tailwind v4 + shadcn/ui · Supabase(Postgres) · NextAuth v5 Google · Vercel.

**LLM API 키가 없다.** 변경 요약은 경로와 바뀐 `##` 섹션, 증감 줄 수를 조합해 구조적으로
만든다. 쓰기 경로에 LLM을 넣으면 LLM이 멈출 때 편집도 함께 멈춘다.

## 문서

**`SPEC.md`와 `PLAN.md`는 이 레포에 없다.** Cushion 자신이 갖고 있다. 이 도구가 실제로 쓸 만한지
스스로 겪어 보려고 그렇게 두었다(dogfooding, `D-011`).

| 문서 | 어디에 | 담는 것 |
|---|---|---|
| `SPEC.md` | [Cushion](https://cushion-archive.vercel.app/libraries/cushion/SPEC.md) | 무엇을·왜. 데이터 모델, MCP 툴 명세, 검증 항목 |
| `PLAN.md` | [Cushion](https://cushion-archive.vercel.app/libraries/cushion/PLAN.md) | 현재 상태, 다음 작업, **결정 로그** |
| [`AGENTS.md`](AGENTS.md) | 레포 | 코드를 읽어서는 알기 어려운 규칙과 함정 |
| [`supabase/migrations/`](supabase/migrations) | 레포 | DB 스키마의 원본 |

**앞의 두 문서를 보려면 그 라이브러리의 멤버여야 한다.** 이것이 이 설계의 비용이다.
클론만으로는 스펙을 읽을 수 없다.

기능을 제안하기 전에 Cushion의 `PLAN.md` 결정 로그를 먼저 읽는다. LLM 요약과 임베딩 검색,
폴링 구독, 자동 병합은 이미 기각됐고 각 항목에 근거와 재검토 조건이 같이 적혀 있다.
**뒤집힌 결정(D-001 → D-011)도 지우지 않고 남겨 두었다.** 무엇을 근거로 정했고 그 근거의
어디가 틀렸는지가 남아야 같은 자리에서 같은 실수를 반복하지 않기 때문이다.
