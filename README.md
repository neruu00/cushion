# Cushion

> 쿠션이 완충해 토큰을 줄인다.

**에이전트를 1차 독자로 삼은 문서 도서관이다.** 스펙과 ADR, 런북, 회의록, 용어집처럼
흩어지기 쉬운 프로젝트 문서를 한곳에 모아 두고, 팀에는 변경 알림을 보내고,
에이전트에는 MCP로 **필요한 조각만** 읽고 쓰게 한다.

목적은 하나다. 에이전트가 같은 문서를 세션마다 컨텍스트에 다시 싣느라 소모하는 토큰을
줄이는 것이다.

**쓰는 데 이 레포는 필요하지 않다.** 웹에서 로그인하고 토큰 하나를 발급하면 끝난다.

**<https://cushion-archive.vercel.app>** · [개요](https://cushion-archive.vercel.app/docs)
· [설치](https://cushion-archive.vercel.app/docs/install)

## 무엇을 해결하나

에이전트에게 스펙을 읽히는 흔한 방법은 파일 전체를 컨텍스트에 넣는 것이다. 그런데 한 번의
작업에 필요한 부분은 대개 섹션 하나고, 다음 세션에는 같은 문서를 처음부터 다시 싣게 된다.
문서가 자랄수록 이 비용은 작업 수에 비례해 늘어난다.

Cushion은 그 과정을 **목차 한 번 + 필요한 섹션 하나씩**으로 바꾼다. 목차는 세션당 한 번만
읽으면 되므로 작업이 늘어날수록 격차가 벌어진다.

**이 레포 자신의 문서로 측정한 값**은 문서를 전부 불러올 때와 비교해서
**20% 미만, 곧 5배 이상 절감**이다(작업 3건 기준, 목차 1회 + 필요한 섹션 1개씩).

숫자를 코드에 고정하지는 않는다. 측정 대상이 이 레포의 문서라서 문서가 자라면 값도 함께
움직이기 때문이다. `pnpm acceptance`가 실행될 때마다 다시 측정한다.

```
                       Cushion
                    ─────────────
사람     ─웹 편집→   documents          (원본)  ─MCP→  에이전트
에이전트 ─doc_put→   document_versions  (이력)  ─→     웹 화면
                     sync_events        (요약)  ─→     Mattermost · Discord
```

## 설치

먼저 <https://cushion-archive.vercel.app>에서 Google로 로그인하고 `/settings/tokens`에서
토큰(`cshn_pat_…`)을 발급한다. **토큰은 그때 한 번만 보인다.** 서버에는 sha256 해시만
남아서 다시 꺼낼 수 없고, 잃어버리면 재발급하면 된다(재발급하는 순간 이전 토큰은 무효다).

### Claude Code — 두 줄

```
/plugin marketplace add neruu00/cushion
/plugin install cushion@cushion
```

플러그인이 MCP 서버 설정과 스킬을 함께 들고 온다. 토큰은 `install` 도중에 물어보고
Claude Code의 보안 저장소에 들어가므로 **평문 설정 파일에 남지 않는다.**

플러그인으로 들어온 스킬은 이름 앞에 플러그인 이름이 붙는다 — `/cushion:cushion-use`처럼
부른다.

### 그 외 클라이언트 — 세 단계

Cushion은 URL과 `Authorization: Bearer` 헤더만 있으면 되는 Streamable HTTP 서버라
클라이언트를 가리지 않는다. `/settings/tokens`가 Claude Code와 Antigravity, Codex CLI용
스니펫을 **토큰이 채워진 채로** 만들어 준다.

```
# ① 연결하기
claude mcp add --transport http --scope user cushion https://cushion-archive.vercel.app/api/mcp \
  --header "Authorization: Bearer cshn_pat_..."

# ② 스킬 설치하기 — 에이전트에게 그대로 보낸다
https://cushion-archive.vercel.app/api/skills 를 받아서 files의 각 항목을
~/.claude/skills/<path> 경로에 저장해 줘.

# ③ 어느 라이브러리를 볼지 정하기 — 에이전트에게 그대로 보낸다
/cushion-use
```

①에 토큰을 직접 넣는 이유는 이 명령이 쓰는 `~/.claude.json`이 커밋되지 않기 때문이다.
평문으로 남으므로 유출되면 재발급한다.

**③이 가장 안 보이지만 가장 중요하다.** 툴이 있다고 해서 에이전트가 알아서 쓰지는 않는다.
로컬에 문서가 없는 것이 이 구조의 정상 상태라, `AGENTS.md`의 한 줄이 Cushion을 찾게 만드는
유일한 신호다. `/cushion-use`가 `git remote`를 보고 그 줄을 대신 넣어 준다.

### 팀 전체에 배포할 때

라이브러리 설정 화면이 `.mcp.json` 스니펫을 준다. 그 파일은 커밋되므로 토큰을 넣지 않고
환경변수(`CUSHION_TOKEN`) 확장을 쓴다. 팀원이 `AGENTS.md`를 이미 커밋해 뒀다면 합류하는
사람은 ①만 하면 된다.

프로젝트 스코프 설정은 user 스코프를 덮어쓴다. 개인이 이미 연결해 둔 상태에서 `.mcp.json`만
받으면 `CUSHION_TOKEN` 없이는 그 프로젝트 안에서만 401이 난다.

## 사용법

### 에이전트가 쓰는 툴

| 툴 | 하는 일 |
|---|---|
| `doc_outline` | 문서 목록과 `##` 헤딩만 준다. **이것을 먼저 부른다** |
| `doc_get` | 문서 하나 또는 섹션 하나. `if_none_match`가 맞으면 본문 대신 `unchanged`를 준다 |
| `doc_search` | 매칭된 섹션 상위 몇 개를 준다 |
| `doc_changes_since` | 커서 이후의 변경 요약을 준다. 커서는 서버가 기억한다 |
| `doc_put` | 생성하거나 수정한다. 기존 문서는 `base_sha`가 필수이고, 어긋나면 거부하며 현재 sha를 준다 |
| `doc_delete` | 삭제한다. 이전 본문은 이력에 남는다 |
| `library_create` | 새 라이브러리를 만든다. 부른 토큰의 주인이 첫 멤버가 된다 |

**토큰 하나로 읽고 쓴다.** 그래서 유출되면 열람만이 아니라 문서 훼손까지 가능하다.
`last_used_at`이 갱신되므로 그 토큰이 아직 살아 있는지 화면에서 확인할 수 있다.

구독에는 폴링도 상시 연결도 쓰지 않는다. 밀렸을 때만 아무 툴 응답 끝에 한 줄이 붙는다.

```
[stale] <library>: <path> changed — call doc_changes_since
```

밀리지 않았으면 그 줄이 아예 없으므로 **추가 비용이 0이다.**

### 스킬

에이전트가 툴을 어떻게 써야 하는지 아는 것과, 문서를 잘 정리하는 것은 다른 일이다.
스킬이 그 두 번째를 맡는다.

| 스킬 | 언제 |
|---|---|
| `cushion` | 문서를 읽거나 쓸 때. 에이전트가 알아서 부른다 |
| `/cushion-use` | 이 프로젝트가 쓸 라이브러리를 정해 `AGENTS.md`에 적어 둘 때 |
| `/cushion-list` | 접근할 수 있는 라이브러리를 볼 때 |
| `/cushion-new` | ADR·런북·회의록 같은 새 문서를 관례에 맞게 만들 때 |
| `/cushion-capture` | 이번 작업에서 확정된 결정과 함정을 문서에 반영할 때 |
| `/cushion-compact` | 더는 일하지 않는 내용을 문서에서 걷어낼 때 |
| `/cushion-divide` | 굵어진 섹션을 쪼개 에이전트가 읽는 단위를 줄일 때 |

### 사람이 쓰는 화면

| 화면 | 하는 일 |
|---|---|
| `/dashboard` | 라이브러리 목록. 여기서 새로 만든다 |
| `/[library]` | 문서 목록. 보기는 서버에서 렌더하므로 열람에 에디터가 실리지 않는다 |
| `/[library]/edit/…` | 편집. 에이전트의 `doc_put`과 **같은 경로**를 지나므로 이력도 알림도 같이 남는다 |
| `/[library]/history/…` | 버전 사이 변경을 hunk로 보여준다. 여기서 되돌린다 |
| `/[library]/changes` | 그 라이브러리의 변경 목록 |
| `/settings/tokens` | 토큰 발급·재발급, 마지막 사용 시각 |

### 변경 알림

라이브러리마다 Mattermost 또는 Discord 웹훅 URL을 하나 넣어 두면 **편집마다 한 통**
나간다. 경로와 바뀐 `##` 섹션, 증감 줄 수를 조합한 구조적 요약이라 어느 코드가 영향받는지
사람이 판단할 수 있다.

묶지 않는 이유는 시간이 작업의 대용물로 너무 거칠기 때문이다. 예전에는 시간 창으로
디바운스했는데, 창이 라이브러리 단위여서 그 안에 들어온 남의 무관한 작업까지 한 통에
섞였다. 조용히 하고 싶으면 웹훅 URL을 비운다.

### 이력과 되돌리기, 그리고 백업

**문서의 원본이 여기에 있다.** 되돌릴 git이 없다. 그래서 git이 공짜로 주던 것을 대신할
장치를 따로 두었다.

- **이력**: 덮어쓰기 전에 이전 본문을 남긴다. 문서를 지워도 이력은 남는다.
  되돌리기는 덮어쓰기가 아니라 새 저장이라 "언제 무엇으로 되돌렸나"도 남는다
- **동시 편집**: 읽을 때 받은 `sha`를 쓸 때 되돌려 받는다. 어긋나면 **거부**하고
  병합하지 않는다. 브랜치가 없어 병합할 근거가 없기 때문이다
- **내보내기**: `GET /api/export`. 접근할 수 있는 문서 전체를 한 파일로 준다.
  세션으로도 토큰으로도 부를 수 있어서 백업 스크립트에 걸어 둘 수 있다.
  **git이 없으므로 이것이 유일한 백업이다**

## 팀과 권한

**로그인하면 누구나 라이브러리를 만들 수 있다.** `/dashboard`의 "새 라이브러리"로 만들고,
만든 사람이 첫 멤버이자 소유자가 된다.

팀원은 라이브러리 화면의 **멤버** 다이얼로그에서 초대한다. 이메일을 하나씩 넣거나, 초대 링크
하나를 만들어 채널에 던져도 된다. 초대와 제거, 설정 변경은 소유자만 할 수 있고, 자기 자신을
빼고 나가는 것은 누구나 할 수 있다.

**멤버가 아닌 이메일은 로그인해도 아무것도 못 본다.** 권한 없는 라이브러리는 403이 아니라
404로 답한다 — 403은 그 라이브러리가 존재한다는 사실을 알려주기 때문이다.

예외는 소유자가 공개 읽기를 켠 라이브러리뿐이다. 그때는 링크를 아는 누구나 로그인 없이
문서를 읽을 수 있지만, 쓰기와 이력, 멤버 목록은 그대로 멤버에게만 열린다.

**읽기와 쓰기의 기준이 같다.** 볼 수 있는 사람은 고칠 수 있고, 역할을 더 나누지 않는다.

문서는 라이브러리 화면의 "새 문서"로 만들거나 에이전트가 `doc_put`으로 만든다. 경로는
`.md`로 끝나야 한다. 목차와 섹션 조회가 전부 마크다운을 전제하기 때문이다.

라이브러리 권한은 토큰에 굽지 않는다. 요청할 때마다 멤버 목록을 다시 조회하므로 **멤버에서
빼면 토큰을 재발급하지 않아도 다음 호출부터 바로 막힌다.**

## 직접 띄우려면

쓰려고 왔다면 여기까지 읽을 필요가 없다. 아래는 자기 인프라에 올리려는 사람을 위한
안내다. 준비물은 Node 24 이상, pnpm, Supabase 프로젝트, Google OAuth 클라이언트다.

```bash
pnpm install
cp .env.example .env.local     # 값을 채운다
pnpm dev
```

`SUPABASE_SERVICE_ROLE_KEY`에는 반드시 **`service_role` 키**를 넣는다. anon 키를 넣으면
RLS 정책이 0개라서 모든 읽기가 빈 결과로, 모든 쓰기가 거부로 끝나는데 **에러가 나지 않아
조용하다.** "화면이 비어 있다" 또는 "아무 일도 일어나지 않는다"면 이 키부터 확인한다.

`supabase/migrations/0001_schema.sql`을 Supabase SQL Editor에서 실행한다(멱등하다).
`ADMIN_EMAILS`에 넣어 둔 이메일로 로그인하면 `/admin`이 열린다 — 전체 조망과 내보내기,
요청 로그와 사용량이 거기 있다. **이 값이 비면 전원 거부다**(fail-closed).

| 목적 | 명령 |
|---|---|
| 개발 서버 | `pnpm dev` |
| 전체 검증 | `pnpm verify` (타입 + 린트 + 테스트 + 빌드) |
| 인수 검증 | `pnpm acceptance` (SPEC §11을 실 DB로 검증하며, dev 서버가 떠 있어야 한다) |

스택은 Next.js **16** App Router · Tailwind v4 + shadcn/ui · Supabase(Postgres) ·
NextAuth v5 Google · Vercel이다.

**LLM API 키가 없다.** 변경 요약은 경로와 바뀐 `##` 섹션, 증감 줄 수를 조합해 구조적으로
만든다. 쓰기 경로에 LLM을 넣으면 LLM이 멈출 때 편집도 함께 멈춘다.

Claude Code 플러그인 매니페스트는 `.claude-plugin/`에 있다. 자기 인프라에 올렸다면
`plugin.json`의 URL과 `lib/snippets.ts`의 레포 slug를 자기 것으로 바꾼다.

## 문서

**`SPEC.md`와 `PLAN.md`는 이 레포에 없다.** Cushion 자신이 갖고 있다. 이 도구가 실제로 쓸 만한지
스스로 겪어 보려고 그렇게 두었다(dogfooding, `D-011`).

| 문서 | 어디에 | 담는 것 |
|---|---|---|
| `SPEC.md` | [Cushion](https://cushion-archive.vercel.app/libraries/cushion/SPEC.md) | 무엇을·왜. 데이터 모델, MCP 툴 명세, 검증 항목 |
| `PLAN.md` | [Cushion](https://cushion-archive.vercel.app/libraries/cushion/PLAN.md) | 현재 상태, 다음 작업, **결정 로그** |
| [`AGENTS.md`](AGENTS.md) | 레포 | 코드를 읽어서는 알기 어려운 규칙과 함정 |
| [`supabase/migrations/`](supabase/migrations) | 레포 | DB 스키마의 원본 |

**앞의 두 문서를 보려면 그 라이브러리의 멤버여야 한다.** 이것이 이 설계의 비용이다.
클론만으로는 스펙을 읽을 수 없다.

기능을 제안하기 전에 `PLAN.md`의 결정 로그를 먼저 읽는다. LLM 요약과 임베딩 검색, 폴링 구독,
자동 병합은 이미 기각됐고 각 항목에 근거와 재검토 조건이 같이 적혀 있다.
**뒤집힌 결정(D-001 → D-011)도 지우지 않고 남겨 두었다.** 무엇을 근거로 정했고 그 근거의
어디가 틀렸는지가 남아야 같은 자리에서 같은 실수를 반복하지 않기 때문이다.
